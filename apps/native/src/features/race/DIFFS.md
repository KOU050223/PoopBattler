# 試作と docs/race.md の食い違い（コース生成）

試作（Version 5）どおりに実装している。docs 側を直すか試作側を直すかは未決。

- docs 2章は「向きは曲率の累積」とだけ書くが、試作は曲率を足してから点を記録するので、区間の最初の点の向き h にはその点の曲率がすでに入っている
- docs 2章はつり橋の出口を「なだらかにつなぐ」とするが、試作は区間の最後の点にも `smooth(1/6)` が残り（高さ約0.096m）、次の区間の先頭で0に落ちる。境目の段差テストの閾値はこれに合わせて0.1
- docs 2章は見るだけのS字を「区間ごとに左右反転」とするが、試作は地形ではなく見るだけの区間の番号（0,1,2,3）の偶奇で決める。最初の3つに必ずS字が入るので、S字の向きは区間番号しだいで右にも左にもなる
- ミニゲームのS字は反転せず、常に同じ向きから始まる（試作も同じ）
- 区間の長さが30の倍数なのは見るだけの区間（90/150/150/150）だけ。スタート32mとミニゲーム48mは対象外（ミニゲームS字の周期は24なので48は割り切れる）
- 時間まわりの上限（1フレームの実時間 0.05 秒 = 6ステップ）は試作の `Math.min(0.05, dt)` に合わせた。docs には上限の記述がない

# 試作との食い違い（物理・操舵・ぶつかり合い・追い抜き・エンジン）

- 試作の `Math.random` は、すべてシード付きの rng に置き換えた。引く順番は コース → 相手のステータス → レーン → グリッド → 調子の位相 → （走行中）ぶつかり・ハードル・ミニゲームの出来
- 相手のステータスは試作どおり「プリセット7種から1つを選んで並びを入れ替える」を7体分。7種を1つずつ使うわけではないので、同じ形の相手が重なることがある
- 相手の名前・色は持たない（描画側の仕事）。試作の `squash`・火花・カメラの揺れも持たず、`bump` などの出来事だけを返す
- 試作の `mg.perf` / `r.zonePerf` は `Runner.perf` に一本化した。区間に入った時点で相手は乱数、自分は 0.5（ダッシュ 0.3）にして、自分の値は `setPerf` コマンドで上書きする。`fixedPerf` を渡すと全員その値に固定する
- 試作のジャンプ `simTime - jumpAt < 0.5` は、`jumpUntil`（終わる時刻）との比較に置き換えた。転倒・加速も同じく `stumbleUntil` / `boostUntil`
- 試作の「追い抜き相手」はオブジェクトの参照、こちらは走者の番号（`passingIndex`）
- 試作は区間を出ても相手の `zoneIndex` を残すが、こちらは -1 に戻して `zoneExit` を出す（自分のミニゲーム終了の合図に使うため）。見た目の挙動は同じ
- 自分のハードルの通過（跳ばずに通ったら転ぶ）と、早跳びの転倒（`tripS`）はミニゲーム側（I255-03）で `jump` / `stumble` コマンドとして指示する。エンジンが自動で動かすのは相手のハードルだけ
- 試作の `trackRanks` が持つ「0.6m 離れるまで前後を入れ替えない」判定は、エンジンの `isAheadOfPlayer` に移した。順位が変わると `rankChange`、先頭が変わると `leaderChange` を返す
- 試作は走者ごとに `draftAmount` を2回呼んでいたが、同じ値なので1回にした

# 試作との食い違い（ミニゲーム・実況・session）

- S字で外したときの減速は、試作の `stumbleUntil = 今 + 0.3` に合わせて `RaceCommand` の `slow` を足した（転倒と同じ減速で、`stumble` イベントも「ドテッ」も出さない）
- ハードルのタップが 0.6m より近い場合も、試作どおり「早すぎ」（出来0.1・ハードルで転ぶ）。docs は「それより手前」としか書かない
- ハードルの自分の通過管理は、`Runner.doneHurdles` ではなくミニゲームの state（`doneIndices`）が持つ。エンジンは自分のハードルを見ない
- 連打の速さは窓（0.8秒）の中のタップ数 ÷ 0.8 なので、取りうる r は 0 / 1.25 / 2.5 …。docs の「毎秒2回以下で目標0」は、窓に入るタップが1回以下（毎秒1回ほど）のとき
- 実況の時間は、試作で混ざっていた実時間（ロック・大きな文字・ぶつかり）とシミュレーション時間（スリップストリームの3秒）をすべて実時間 ms にそろえた
- 大きな文字の 0.9 秒の間隔は、順位変化と「ゴツン！」で共有する（試作の `lastFx`）。区間の評価・ハードルやS字の結果の文字は間隔なしで出す
- 「アップ」で集中線が出る条件はカメラの状態なので、`CommentaryInput.isCloseUp` として呼び出し側（カメラ）から受ける
- 試作の壁の実況（「壁にこすった！」「落ちそう！」）と、スタート前の「今日の順番」「スタート！」は、エンジンに出来事が無い・レースにカウントダウンが無いので作っていない
- ミニゲームのパネルを、区間の `announceAhead`（16m）手前の予告から「じゅんび中」の見た目で出す（試作は区間に入ってから。つり橋が3秒で終わり、実機で操作が間に合わなかったため）。判定・perf・矢印の制限時間は試作のまま

# 試作との食い違い（カメラ）

- 試作の Math.random は rng に置き換えた
- 試作はコース上の点を ptAt(s) で直接引く。ここでは CameraInput.pointAt として受け取る
- 試作の時刻は performance.now（実時間）。ここでは update の dt を足した内部時計（強制切り替え・1カットの長さ用）
- 試作の shot 名 'chase' は、ミニゲーム中・ゴール後・抽選の「後ろ追い」で共通。種類は同じでも ミニゲーム中は別の寄り方（試作の 'mg'）なので、kind は 'minigame' と 'chase' に分けた
- 1カットの長さは試作どおりグループごと（全体 2.8〜3.4、プレイヤー 2.4〜3.2、ライバル 2.4〜2.8）。 race.md の「2.4〜3.4秒」はその合算の範囲
- 試作はスタート前を game.phase で判定。ここでは入力の isPreStart
- 画角の揺れ（fovKick）は試作の「抜いた」の -10 度だけ入れた。画面の揺れ（shake）は持たない
- 試作は強制中でもミニゲーム中の「ぶつかった」では切り替えない（!mg.active）。ここでは呼び出し側が trigger を null にして渡す前提で、camera.ts では判定しない
- 強制切り替えの trigger は「起きたフレームだけ」非 null で渡す。毎フレーム渡すと強制が延び続ける
- 表示割合は、抽選だけなら全体/プレイヤー/ライバル ≒ 重みどおり、強制を混ぜると 17/74/9 付近（camera.test.ts）

# 実測値（ボット対戦・各条件 150 レース・シード 12345 から連番・衝突あり）

`simulate.ts` の `simulateRaces` で測り、`npm run test:balance`（`simulate.balance.test.ts`、1〜2分）で基準値の ±0.5 を確かめる。ボットは `bots.ts`、60fps で `runFrame` を回し、入力は `InputCommand` で渡す。150 本は平均のぶれが ±0.15 ほどに収まる本数（SD 約2、SE ≒ 0.16）。

基準値は「試作の `makeCourse` / `step` / `mg` を node で同じボットで回した値」。docs の旧値（パワー 4.1・技術 4.5・体力 4.8）を取った時の機械操作が試作に残っておらず再現できなかったため、docs を実測値に更新した（2026-10-30）。

| 条件 | 基準値（試作を node で） | 移植 |
| --- | --- | --- |
| バランス・完璧 | 1.40 | 1.42〜1.50 |
| バランス・そこそこ | 3.14 | 2.98 |
| バランス・何もしない | 7.63 | 7.65 |
| 二刀流・そこそこ | 5.54 | 5.75〜5.95 |
| パワー型・そこそこ | 4.77 | 4.71〜5.04 |
| 技術型・そこそこ | 4.00 | 3.78〜3.86 |
| 体力型・そこそこ | 3.93 | 3.98〜4.50（試行ごとのぶれが大きい） |

並びは 技術型 ≒ 体力型 < パワー型。衝突を切っても傾向は変わらない。

# 試作との食い違い（入力）

- スワイプは「大きい軸の移動量が max(48dp, 画面幅の12%) を超える」かつ「大きい軸が小さい軸の1.5倍以上」のときだけ。試作は移動距離が 28 CSS px を超えれば向きを問わず通り、実機（Pixel 9a）では指がずれただけでスワイプ扱いになったため（input.ts）
- スワイプは条件を初めて満たした瞬間に出し（試作は pointerup で判定）、押した時点の矢印にだけ効かせる。押している間にその矢印が時間切れになったら捨てる。離すまで待つと時間切れが挟まり、次の矢印まで巻き込んだため（input.ts / minigames/swipe.ts）

# 試作との食い違い（3D ステージ）

- 観客はトイレットペーパー（円柱）ではなく、2Dのうんちくん4種類（茶色・ぼうし・サングラス・金色で応援）をカメラに向く板で描く。絵柄ごとに InstancedMesh 1つ（計4描画）。走者の近くで跳ねるのは試作と同じ。ゴールでの特別な動きはまだ付けていない
- 観客は試作の「12m ごとに左右交互」ではなく、12m ごとに左右とも置く。試作どおりだと実機で周りが寂しかったため。インスタンスは 56〜60 → 112〜120 個（シード 1・7・42）
- 走者の大きさは、GLB（poopm_base）を idle で再生して測った横幅 3.07（腕込み。体だけなら 2.02）を当たり判定の直径 1.5m に合わせて 0.49 倍にした。試作の青い丸っこい体は半径 0.78 で、これと同じ横幅になる
- 試作の地面・空・フォグ・縁石・ゲート・看板・ハードルの色と寸法は、すでに数値が試作と一致している（変えていない）。ゲートと看板は文字が無く色の帯だけ（文字は後続のオーバーレイ）
- 画角はショットごとに試作と同じ値（40〜62度）で、縦長では `fitFov` で広げる（camera.ts）。試作の 62 度はカメラを作った時の初期値と後ろ追い・ミニゲームのショットの値
