# 試作と docs/race.md の食い違い（コース生成）

試作（Version 5）どおりに実装している。docs 側を直すか試作側を直すかは未決。

- docs 2章は「向きは曲率の累積」とだけ書くが、試作は曲率を足してから点を記録するので、区間の最初の点の向き h にはその点の曲率がすでに入っている
- docs 2章はつり橋の出口を「なだらかにつなぐ」とするが、試作は区間の最後の点にも `smooth(1/6)` が残り（高さ約0.096m）、次の区間の先頭で0に落ちる。境目の段差テストの閾値はこれに合わせて0.1
- docs 2章は見るだけのS字を「区間ごとに左右反転」とするが、試作は地形ではなく見るだけの区間の番号（0,1,2,3）の偶奇で決める。最初の3つに必ずS字が入るので、S字の向きは区間番号しだいで右にも左にもなる
- ミニゲームのS字は反転せず、常に同じ向きから始まる（試作も同じ）
- 区間の長さが30の倍数なのは見るだけの区間（90/150/150/150）だけ。スタート32mとミニゲーム48mは対象外（ミニゲームS字の周期は24なので48は割り切れる）
- 時間まわりの上限（1フレームの実時間 0.05 秒 = 6ステップ）は試作の `Math.min(0.05, dt)` に合わせた。docs には上限の記述がない

# 試作との食い違い（物理・操舵・ぶつかり合い・追い抜き・エンジン）

- 試作の `Math.random` は、すべてシード付きの rng に置き換えた。引く順番は コース → 相手のステータス → レーン → グリッド → 調子の位相 → （走行中）ぶつかり・ハードル・ミニゲームの出来
- 相手のステータスは試作どおり「プリセット7種から1つを選んで並びを入れ替える」を7体分。7種を1つずつ使うわけではないので、同じ形の相手が重なることがある
- 相手の名前・色は持たない（描画側の仕事）。試作の `squash`・火花・カメラの揺れも持たず、`bump` などの出来事だけを返す
- 試作の `mg.perf` / `r.zonePerf` は `Runner.perf` に一本化した。区間に入った時点で相手は乱数、自分は 0.5（ダッシュ 0.3）にして、自分の値は `setPerf` コマンドで上書きする。`fixedPerf` を渡すと全員その値に固定する
- 試作のジャンプ `simTime - jumpAt < 0.5` は、`jumpUntil`（終わる時刻）との比較に置き換えた。転倒・加速も同じく `stumbleUntil` / `boostUntil`
- 試作の「追い抜き相手」はオブジェクトの参照、こちらは走者の番号（`passingIndex`）
- 試作は区間を出ても相手の `zoneIndex` を残すが、こちらは -1 に戻して `zoneExit` を出す（自分のミニゲーム終了の合図に使うため）。見た目の挙動は同じ
- 自分のハードルの通過（跳ばずに通ったら転ぶ）と、早跳びの転倒（`tripS`）はミニゲーム側（I255-03）で `jump` / `stumble` コマンドとして指示する。エンジンが自動で動かすのは相手のハードルだけ
- 試作の `trackRanks` が持つ「0.6m 離れるまで前後を入れ替えない」判定は、エンジンの `isAheadOfPlayer` に移した。順位が変わると `rankChange`、先頭が変わると `leaderChange` を返す
- 試作は走者ごとに `draftAmount` を2回呼んでいたが、同じ値なので1回にした

# 試作との食い違い（ミニゲーム・実況・session）

- S字で外したときの減速は、試作の `stumbleUntil = 今 + 0.3` に合わせて `RaceCommand` の `slow` を足した（転倒と同じ減速で、`stumble` イベントも「ドテッ」も出さない）
- ハードルのタップが 0.6m より近い場合も、試作どおり「早すぎ」（出来0.1・ハードルで転ぶ）。docs は「それより手前」としか書かない
- ハードルの自分の通過管理は、`Runner.doneHurdles` ではなくミニゲームの state（`doneIndices`）が持つ。エンジンは自分のハードルを見ない
- 連打の速さは窓（0.8秒）の中のタップ数 ÷ 0.8 なので、取りうる r は 0 / 1.25 / 2.5 …。docs の「毎秒2回以下で目標0」は、窓に入るタップが1回以下（毎秒1回ほど）のとき
- 実況の時間は、試作で混ざっていた実時間（ロック・大きな文字・ぶつかり）とシミュレーション時間（スリップストリームの3秒）をすべて実時間 ms にそろえた
- 大きな文字の 0.9 秒の間隔は、順位変化と「ゴツン！」で共有する（試作の `lastFx`）。区間の評価・ハードルやS字の結果の文字は間隔なしで出す
- 「アップ」で集中線が出る条件はカメラの状態なので、`CommentaryInput.isCloseUp` として呼び出し側（カメラ）から受ける
- 試作の壁の実況（「壁にこすった！」「落ちそう！」）と、スタート前の「今日の順番」「スタート！」は、エンジンに出来事が無い・レースにカウントダウンが無いので作っていない
