# 試作と docs/battle.md の食い違い・整理した箇所

試作（実験版 Version 15）どおりに実装している。docs 側を直すか試作側を直すかは未決。

## 数値・ルールの食い違い

- docs 2.13 は本気の1番を約50秒・序盤を約35秒とするが、試作ロジックの実測は本気 38.2秒・序盤 31.2秒（末尾の実測値）
- docs 1・4.1 は方向を左右の2つとするが、試作は7要素の `dirSpec` を持ち、`act('tsuki')` の方向省略時は 3（上: 構え480ms・押す量24）になる
- docs 2.14 は「同じ手は避ける」とするが、NPC の `last` キーは突きが `tsuki0` / `tsuki6` なので重み表の `tsuki` に当たらず、避けるのは四つといなしだけ
- 皮すべらせ（パリィ扱い）は土俵際でも熱にならず、自分の硬直も付かない（docs 2.7 は「パリィかいなし」とだけ書く）
- docs 4.4 はヒットストップをロジックが持つとするが、`freeze` は update() が減らすだけで、立てるのは UI の責務（試作もロジック外で立てている）
- 同じステップ内の処理順は東→西で固定のため、同時に発動した手は東が先に判定される

## 死んだ分岐・未使用（挙動を変えずに整理）

- `act` の `kind==='parry'` 専用の後段（`CFG.parry.act * (0.6+0.4*repMult)`）は、手前の早期 return で到達不能なので削除
- `CFG.parry.cost`（10）は未使用（守りは息を消費せず、いなし中の毎秒4だけ減る）。値は残した
- `parry()` 内の `f.sp.fav==='dodge'`（×1.8）は fav に dodge が無く常に偽なので削除
- `FX.guard` は試作の中でも呼ばれていないので、イベントにしていない
- `Difficulty` の `freeze / punish / rush / gap` は3つの番付のどれにも設定が無く、常に既定値。型は optional のまま
- `modeOf` の `g.mode||MODES[1]` は `Game.mode` を必須にし、`newGame` の既定を本気にして表現
- `CFG.dodge` と `act('dodge')` は UI から使われないが、試作のロジックに残っているので残した

## 実測値（幕下 vs 幕下・NPC同士・2000番・本気モード・シード 12345）

組み合わせは種族 3×3 を均等に回し、`simulate.ts` の `simulateMatches` で測った。試作ロジックをそのまま Node で同条件に回した結果とも、平均・勝率が完全に一致した。

- 決着しなかった取組: 0 / 2000
- 平均取組時間: 38.19秒（最長 374.2秒）
- 東の勝率: 48.6%
- 種族別勝率（同種対戦を含む）: カレー 54.8% / バナナ 38.0% / ガンコ 57.2%

参考（序盤モード・同条件・時間倍率を戻した実時間）: 平均 31.18秒 / 最長 333.1秒 / 東の勝率 50.1% / カレー 48.3% / バナナ 46.6% / ガンコ 55.1%
