# うんちくん相撲（バトル刷新案・草案）

現行のバトルは [`battle.md`](./battle.md)、直前の綱引き案は [`battlever2.md`](./battlever2.md)。ここは壁打ちで固まった次の方向をまとめる。未確定の点は末尾に置く。

## 解きたい問題

今のバトルが単調なのは、仕組みのせいではなく**個体に特殊性がない**から。個体の差は HP / Power / Speed と属性だけで、「この子だから勝てた」が生まれない。綱引き案（v2）も、スキルが属性単位なので同じ問題が残る。

ポケモンや妖怪ウォッチで集めたくなるのは、キャラごとに動きが違うから。刷新の軸はここに置く。

## 方向性

**トイレで記録し、あとで相撲を取る育成バトル。**

- 相撲部屋のうんちくん（力士）を育て、番付を上げる
- 取組は「じゃんけん＋シェイク」のラウンド制。演出は3D
- PVPはサーバー判定で同期する

### 検討して外した案

| 案 | 外した理由 |
| --- | --- |
| 育成のみ | バトルがないと遊ぶ目的が弱い。子供が好きなのはバトル |
| ピクミン式の多人数攻城 | 群れにすると1体ごとの個性が薄まり、解きたい問題とぶつかる。「記録が軍勢になる」というテーマは良いので、将来のイベントモード候補 |
| ベイブレード式（相棒＋パーツ） | 個性がパーツへ移り、うんちくん本人が入れ物になる。発射後は見守るだけで、同期PVPの手応えもない |
| 綱引き（v2） | 個性が属性単位。1次元の押し合いは、互角の相手だと膠着しやすい |

相撲を選んだのは、体格と取り口がそのまま力士の個性になるから。「便器に押し出す」という v2 の芯も引き継げる。番付・四股名・行司・決まり手といった様式美は、デザイン方針の「妙にちゃんとしている」とも合う。

## ゲームループ

```text
トイレで排便を記録（約5秒）
  ↓ 次にアプリを開いたとき
取組表に対戦相手が届く
  ↓ 好きなときに
取組（じゃんけん＋シェイク）
  ↓ 勝ったら
食事ログを使った仲間化の抽選（既存の仕組みを流用）
  ↓
15番で1場所。8勝で勝ち越し、番付が上がる
```

トイレ中に遊ばせない。毎回トイレでバトルさせるのは面倒なので、トイレでは記録だけにする。これで制限時間付きのじゃんけん、3D演出、同期PVPが入れられるようになる。記録したあとに3秒ほど「土俵に誰か来たみたい…」と気配だけ見せて、記録した瞬間にも小さな手応えを残す。

## 記録と報酬（不正記録の対策）

記録の回数がそのまま報酬になると、嘘の記録が増えてライフログの価値が壊れる。アプリの本来の目的に直結するので、ここは最優先で守る。表示はぼかし、そのうえで裏の仕組みでも稼げないようにする。ぼかすだけだと、試せば法則がばれて子供同士で広まる。

**見せ方**
- 記録と敵を1対1に見せない。「+1敵」や「あと2回で出現」などのカウンターは出さない
- 敵は記録の瞬間ではなく、次にアプリを開いたときに届く

**裏の仕組み**（どれもユーザーには表示しない）
- 取組表に入るのは1日2〜3番まで。超えた分の記録はログとして残すが、報酬にはしない
- 前回から30分以内の記録は報酬の対象外にする
- 連続記録日数で報酬を出す（相手が強くなる・レアが出やすくなる）。日数は1日1回以上は稼げない
- 取組表の上限は15番（1場所分）。ため込みすぎて消化が作業になるのを防ぐ

**記録の中身で相手を決める**：便の状態で出てくる力士の種類を、食事ログの内容で得意手や見た目を変える。適当な連打からは似た相手しか出てこず、正直に記録するのが一番得になる。ただし、体調の悪い日をペナルティにはしない（硬い日は「ガンコうんちくん」が出る、くらいのフレーバーにとどめる）。

**保証**：1日1回記録すれば、必ず最低1番は取れる。ここまでぼかすと、正直に記録している人が「なんで今日は来ないの？」と不満を持つ。

## 取組のルール

### 1合の流れ

```text
1合（約3〜4秒）
  ├ 両者が同時に手を選ぶ（PVPは制限時間2〜3秒）＋シェイク
  ├ サーバーが判定 → 土俵上の位置が動く
  └ 両端末で同じ3D演出を再生（ぶつかり、押し込み、土俵際はスロー）
土俵の外に出るまで繰り返す（3〜6合で決着の想定）
```

土俵上の位置は1次元の数値で持つ。端まで行けば押し出し（便器へ落ちる）。

### 手（三すくみ）

| 手 | 勝つ相手 |
| --- | --- |
| 突き押し | 四つ |
| 四つ | いなし |
| いなし | 突き押し |

### じゃんけんを運ゲーにしない仕組み

純粋なじゃんけんは1/3の運になる。読み合いには、手を偏らせる情報が要る。

| 仕組み | 生まれる読み |
| --- | --- |
| 土俵際補正：押されている側は「いなし」が強くなる | 追い詰めた側は「いなしが来る」と読む。うっちゃりの逆転が生まれる |
| 同じ手を連続で出すと弱くなる | 相手の手の癖を読む |
| 力士の得意手：得意な手は勝ったときに大きく押す。あいこでも押し勝つ | 相手の力士を見て読む |
| 必殺手：1取組で1回だけ。種族固有の決まり手 | いつ切るかが一番の読みどころ |

**得意手と必殺手が「個体の特殊性」の本体。** 例：カレーうんちくんは「押しが得意、必殺は激辛ぶちかまし」のように、種族ごとに戦い方が変わる。

### シェイク

勝敗は手で決め、シェイクは**勝ったときに押す量・負けたときに耐える量**に効かせる。シェイクで勝敗が決まると、ただの腕力ゲームになる。

## PVPの同期

同期するのは「物理」ではなく「手」。3Dの押し合いを物理演算ごと同期すると、モバイル回線では遅延とズレで破綻する。

- ロジックはラウンド制。手を選ぶ時間が2〜3秒あるので、数百ミリ秒の遅延は体感に出ない
- 3Dは判定結果を再生するだけ。端末の性能差やフレーム落ちが勝敗に影響しない
- **手を相手に覗かせない**：Realtimeで互いの手を直接送ると、相手の手が先に届いて後出しされる。手はRPCでサーバーに提出し、両者がそろってから判定、結果だけを配信する。Realtimeは「相手が手を出した」「判定が出た」の通知に限る
- シェイク値はクライアントで偽装できる。サーバー側で上限を決める。友達同士の遊びとしてはそれで十分とする
- NPC戦は制限時間なし。自分のペースで手を選べて、PVPの練習も兼ねる

## 育成と集める要素

| 相撲の要素 | ゲームでの役割 |
| --- | --- |
| 番付（序ノ口〜横綱） | 長期の育成目標。勝ち越しで昇格 |
| 決まり手 | 技を覚えて集める。ポケモンの技に当たる |
| 化粧まわし | ガチャ・交換の対象。見た目の個性 |
| 相撲部屋 | 複数のうんちくんを抱える理由。集める楽しさを残す |

「食べたもので育ち方が変わる」案も有力。野菜を記録すれば野菜系の決まり手を覚える、激辛が続けば激辛形態に分岐する、など。食事ログを付ける動機が「ガチャ確率」から「この子をこう育てたい」に変わり、ライフログと一番かみ合う。

既存の HP / Power / Speed と個体値の抽選は流用できる（例：体格 / 押す力 / 粘り）。新しい列は増やさない方向で考える。

## 3D

R3F・three とリグ付きGLBの規約（[`poopm-3d.md`](./poopm-3d.md)）が既にある。取組では、立ち合いのぶつかり、押し込み、土俵際のスローにカメラワークを使う。3Dはあくまで演出で、ロジックは持たせない。

## 既存への影響

ゲームループの順番が「バトル → 排便記録 → 食事 → ガチャ」から「記録 → 取組表 → 取組 → ガチャ」に変わる。`battle_sessions` まわりのサーバーロジックはほぼ作り直しになる。仲間化の抽選（食事ログ）は流用できる。

## 未確定

- 手は3つで足りるか、4つ目（掴み・はたき込み）を足すか。推しは「基本3手＋1回だけの必殺手」。2〜3秒で選ぶには、4手は重い
- 土俵際で追加シェイク（うっちゃりチャンス）を入れるか

- 「食べたもので育つ」を見た目まで変えるか、技だけにするか

- 数値（押す量、補正倍率、決着までの合数）。UIを作る前にシミュレーションで回して決める

## アーティファクト試作のスコープ

まずはNPC戦の1取組だけで、読み合いが面白いかを確かめる。

- 土俵位置（1次元）、三すくみ、土俵際補正、連続同手の弱体化、得意手、必殺手1回
- シェイクはボタン長押しなどで代用してよい
- 演出は2Dで十分。3Dと同期PVPは、面白さを確認してから
- NPCの思考は単純な確率でいい（得意手に寄せる、土俵際ではいなしを増やす）
