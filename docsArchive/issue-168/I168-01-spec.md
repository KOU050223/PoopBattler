# タスク I168-01: バトル画面の3D化（Issue #168）

## セットアップ（最初にやること）

1. プロジェクトの `CLAUDE.md`（= AGENTS.md と同内容）を読む。特に「作業の進め方」に従うこと

3. ブランチ `issue-168-battle-3d` で作業する（worktree が既にそのブランチなら切り替え不要）

## 背景

戦闘画面（/battle の fight ビュー）のキャラは現在 `BattleFigure` → `PoopmFigure`（PNGパーツ + framer-motion）の2D描画。
`public/assets/poopm_3d/poopm_base.glb` に3Dモデルと戦闘アニメーション11種（idle/attack/hit/heal/special_charge/special_fire/swap_in/swap_out/ko/lose/win）が同梱済み。
これを react-three-fiber で描画する3Dステージに置き換える。

**確定済みの仕様（変更しないこと）:**
- スコープは戦闘画面のみ。仲間化AR演出（companionship-ar-stage.tsx）は2Dのまま触らない
- 個体差は **体色・目・口** のみ再現。頭アクセサリ（head_acc/head_var GLB）は今回対象外
- `heal` クリップは今回使わない（別Issue #199 で使う予定）

## 実装内容

### 1. 依存追加

```bash
npm install three @react-three/fiber @react-three/drei
npm install -D @types/three
```

React 19 + Next 16 対応のバージョン（fiber v9系 / drei v10系）が解決されるはず。`latest` や `*` は使わず、公開から日が浅い版への固定は避ける。

### 2. 新規 `src/features/poopm-3d/`

- `poopm-3d.assets.ts` — `POOPM_3D_GLB = "/assets/poopm_3d/poopm_base.glb"`、クリップ名の定数、`BodyColorId`→カラー HEX の Record、目/口 PNG のパス解決（`/assets/poopm_parts/eyes/poopm_eye_<x>.png`、`/assets/poopm_parts/mouth/poopm_mouth_<x>.png` をそのまま使う）
- `poopm-3d.motion.ts` — 純粋関数。バトル用モーション名 → `{ clip, loop: "repeat" | "once", fadeMs }` のマッピング。three に依存しない形にして vitest で検査できるようにする
- `components/poopm-3d-model.tsx` — 1体分のモデルコンポーネント:
  - `useGLTF` + `SkeletonUtils.clone`（`three/examples/jsm/utils/SkeletonUtils`）でインスタンス化。2体共存させるため scene の clone は必須
  - **GLB に編集残骸がある**: `arm_L_old`, `arm_L_prev`, `arm_L_v2bak`, `hand_L_mitten_bak`, `hand_R_mitten_bak`, `hand_L_old`, `トーラス`, `ICO球.001`, `poopm_rig.001`（第2アーマチュア）, `neutral_bone`, `head_acc` などが残っている。素直に描画すると残滓メッシュが見える。**表示するノード名をホワイトリストで列挙**（`body`, `eye`, `mouth`, `arm_L`, `arm_R`, `leg_L`, `leg_R`, `foot_L`, `foot_R`, `hand_L`, `hand_R` 系とスキンリグ）して、それ以外は `visible = false` にすること。ブラックリストではなくホワイトリストで
  - `poopm_body` マテリアルの baseColor を `color` prop（BodyColorId）で上書き。`poopm_limb` は変えない
  - `eye` / `mouth` プレートのテクスチャを prop で差し替え。`TextureLoader` で読み、`texture.flipY = false`、`texture.colorSpace = THREE.SRGBColorSpace` にしてマテリアルの `map` に設定（glTFマテリアルの transparent/alphaTest は維持）
  - `AnimationMixer` でクリップ名再生。`loop === "once"` は `LoopOnce` + `clampWhenFinished`、終了時（`finished` イベント）に idle へ復帰。`mixer.timeScale` にバトル倍速を掛ける
  - `facing="back"` でモデルを Y 軸180°回転（味方は背中側。顔プレートは自然に裏向きになる）
- `components/poopm-3d-stage.tsx` — `<Canvas>` + ambient/directional 光 + 簡易な床/影。敵 = 遠く・小さめ（奥）、味方 = 近く・大きめ（手前）の2体配置。カメラは固定（やや俯瞰気味、2D版の構図に近い斜め見下ろし）。OrbitControls は付けない
- テスト（vitest、jsdom不使用・node環境で通るものに限る）:
  - `poopm-3d.motion.test.ts` — マッピング表のユニットテスト
  - アセット存在テスト — GLB と参照する目/口 PNG が `public/` にあることを `existsSync` で確認（`battle-figure.test.tsx` の CHARGE_SWIRL_PNG のパターン踏襲）
  - SSR smoke — DOMラッパーを `renderToStaticMarkup` で描いて落ちないこと

### 3. `battle-screen.tsx` の fight ビュー変更

- `min-h-72` のパネル内にある2つの `BattleFigure` を、パネルいっぱいに敷く `<Poopm3DStage>`（`absolute inset-0`）に置き換える
- HPバー（敵=上段右寄せ / 味方=下段左寄せ）、相性ピル、倍速ボタン、必殺ゲージ、踏ん張りゲージ、ChargeSwirl（必殺チャージ中の渦巻き）、BattleControls 等の DOM UI はすべて維持し、Canvas より手前（z-index）に置く
- ステージ本体は `next/dynamic` の `ssr: false` で読み込み、SSRバンドルに three が入らないようにする
- モーション状態を拡張する（現状は idle/hit/attack のみ）。純粋関数として切り出してテスト可能にすること:
  - 敵HP減少 → 敵 `hit` + 味方 `attack`（既存のまま）
  - 味方HP減少 → 味方 `hit` + 敵 `attack`（既存のまま）
  - `playerStance === "special"` → 味方 `special_charge` ループ（発射 `fireSpecial` で `special_fire` 一回 → idle）
  - `enemyStance === "special"` → 敵 `special_charge`（敵の必殺が着弾したら `special_fire`）
  - `activeIndex` 変化 → 味方 `swap_in`（戦闘不能で交代なら先に `ko`）
  - 味方メンバー HP 0 → `ko`
  - 敗北（status defeated）→ 味方 `lose` + 敵 `win`、勝利系 → 味方 `win` + 敵 `ko`
- `BattleFigure` が他から参照されなくなったらファイルごと削除してよい（その場合 battle-figure.test.tsx / battle-figure.motion.* も）。PoopmFigure は仲間化演出等で使っているので残す

### 4. プレビュー頁 `src/app/dev/poopm-3d/page.tsx`

- 開発確認専用。`process.env.NODE_ENV !== "development"` で `notFound()` を返す
- Poopm3DStage を固定propsで描画し、モーション切替・色/目/口の差し替えをUI（簡単なボタン群でよい）から確認できるようにする

## 報告プロトコル（厳守）

- **終わったら成功でも失敗でも必ず1回 `worker_done` を送る**:

```bash
ELECTRON_RUN_AS_NODE=1 /Applications/Orca.app/Contents/MacOS/Orca \
  /Applications/Orca.app/Contents/Resources/app.asar.unpacked/out/cli/index.js \
  orchestration send --to run:run_93710f0a635d --type worker_done \
  --task-id <あなたのtaskId> --dispatch-id <あなたのdispatchId> \
  --outcome succeeded|failed \
  --subject "I168-01" \
  --body "やったこと / 結果 / 残ったこと（3行以内）" \
  --files-modified <変更したファイルのcsv>
```

- **注意**: `orca` コマンドは `/usr/local/bin/orca` のシンボリックリンクが壊れており「Unable to determine Orca.app path from symlink」で失敗する。必ず上記の直接パス（ELECTRON_RUN_AS_NODE=1 + Orca.app 内の cli/index.js）で呼ぶこと
- taskId / dispatchId はディスパッチ時のコンテキストに含まれている。分からなければ `orca orchestration dispatch-show` 系で確認する
- 範囲外の変更・判断に迷う点があれば、実装せず同じ直接パスで `orca orchestration ask` を使って質問する
- 報告本文は3行以内: やったこと / 結果 / 残ったこと
