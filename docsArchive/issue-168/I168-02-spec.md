# タスク I168-02: うんちくん3Dの頭アクセサリ対応（Issue #168 続き）

## 前提

このworktreeには I168-01 の成果がコミット済み（`a17189b`、ブランチ `guriguri00451/issue-168-battle-3d`）。
`src/features/poopm-3d/` に R3F ベースの3Dモデル描画があり、個体差のうち体色・目・口は既に反映されている。
今回は残りの **頭（`appearance.head`、HeadId `hat-a`〜`hat-f`）** を3Dでも反映する。

まずプロジェクトの CLAUDE.md/AGENTS.md と `docs/poopm-3d.md` を読むこと。`npm install` 済みのはずだが念のため確認。

## 資産の実態（調査済み。自分でも確認してよい）

- `public/assets/poopm_3d/head_acc_<id>.glb`（hat-a〜f）: 生成アクセサリ。**原点=ソケット接地点、-Y が正面**。`b_head_acc` ボーンへアタッチする想定
- `public/assets/poopm_3d/head_var_<id>.glb`（hat-a〜f）: 頭ドーム+アクセサリ一体の手作り品。**ベースモデルと同じモデル空間座標（原点=キャラ原点）**
- ベース `poopm_base.glb` の稼働リグには `b_head_acc` ボーンがある（`b_head` の子。glTFノード index 43）。ドキュメントには「ソケット未整備」とあるが、実際にボーンは存在する。**位置・追随が正しいかは /dev/poopm-3d で目視確認する**
- `head_acc`（ボーンではない空ノード、y≈3.87 に浮いた残骸）は**使わない**。現行実装のホワイトリストで既に非表示
- 注意: ベースの `body` メッシュは3段ドーム+カールが1メッシュに焼かれており、頭部分だけ非表示にはできない。`head_var`（ドーム一体型）を載せるとベースの頭と二重になる可能性がある

## やること

1. **実験して採用方式を決める**（/dev/poopm-3d プレビュー頁で目視確認しながら）:
   - 方式A: `head_acc_<id>.glb` を `b_head_acc` ボーン（`getObjectByName`/`SkeletonUtils` 経由でボーンオブジェクトを取得し `add`）にアタッチ。アニメーションで頭に追随するか確認
   - 方式B: `head_var_<id>.glb` をモデル空間原点に配置し、ベースの頭をどう扱うか（二重ドームが見えるか、head_var がベース頭を完全に覆うか）を確認
   - 両方ダメなら「ベースGLBの再生成が必要」として `orca orchestration ask` で報告して止まる（BlenderでのGLB再生成・スクリプト変更はこのタスクの範囲外）
2. 採用方式で `Poopm3DModel` に `head` prop を実装:
   - `appearance.head`（HeadId）→ 対応GLBを `useGLTF` でロード（遅延ロードでよい。Suspense内で）
   - 体色連動: head_var のドーム部分は `poopm_body` マテリアルのため、胴体色変更に追従させること（ドキュメント記載の仕様）
   - clone済みインスタンスごとにアタッチ（個体ごとに違う頭を出せること）
3. `Poopm3DAppearance` に `head: HeadId` を追加し、`battle-screen.tsx` 側は `appearanceForCharacter()` が返す `head` をそのまま通す形にする（呼び出し側は変更不要なはず）
4. `/dev/poopm-3d` プレビュー頁に頭（hat-a〜f）の切替UIを追加
5. `docs/poopm-3d.md` の「既知の問題」節を実態に合わせて更新（採用した方式・b_head_acc の実測結果を1〜3行）
