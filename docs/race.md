# レース：うんちくんカート（ミニゲーム版）

ブラウザ試作で固まったレースを、Native（Expo + React Three Fiber）へ移植するための仕様。試作は [`prototypes/race-minigame.html`](./prototypes/race-minigame.html)（Artifact「うんちくんカート ミニゲーム版」Version 5）で、細かい挙動の正解はこのHTMLにある。数値はすべて試作の値で、調整前提の目安として扱う。

[`game-design.md`](./game-design.md) の「トイレで遊ぶ1分のレース」の中身の案。ループ・報酬・不正対策はそちらが正本。

---

## 1. 概要

- 8体で走る約1分の3Dレース。スマホ縦持ち、片手で遊ぶ
- コースには**ミニゲーム区間が3つ**（4種類から毎回ランダム）と、その間の**見るだけの区間**がある
- ミニゲームの出来は、その場で自分の速さに反映される。見るだけの区間の速さはステータスで決まる
- 走りは物理で決まる。ぶつかり合い（オン・オフ可）、スリップストリーム、追い抜きのAIがある

---

## 2. コース

中心線を1m間隔の点列で持つ。各点は `{x, z, y, h（向き）, k（1mあたりの向きの変化＝曲率）, w（道幅）, s（距離）, kind, zone, terrain}`。

| 順番 | 区間 | 長さ |
| --- | --- | --- |
| 1 | スタート（2列のグリッド、スタートラインは18m地点） | 32m |
| 2 | 見るだけ | 90m |
| 3 | ミニゲーム1 | 48m |
| 4 | 見るだけ | 150m |
| 5 | ミニゲーム2 | 48m |
| 6 | 見るだけ | 150m |
| 7 | ミニゲーム3 | 48m |
| 8 | 見るだけ（ゴールは終端の20m手前） | 150m |

- 道幅は11m。8体が並んでも、抜くための隙間が残る幅にしてある
- **見るだけの区間の地形**：直線・上り坂・S字を1回ずつシャッフルして使い、最後の区間だけランダム
  - 上り坂：`y = 3.2 × sin²(πi/30)`
  - S字：向きの変化 `= 0.8 × (2π/30) × cos(2πi/30)`。区間ごとに左右を反転する
- **区間の長さは周期30mの倍数にする**。割り切れないと、区間の終わりで高さが段差になり、向きもずれたまま次の区間へ続いてしまう
- ミニゲーム区間の形

| 区間 | 形 |
| --- | --- |
| ダッシュ | 直線 |
| ハードル | 直線。区間の30%・58%・86%の位置にハードル |
| つり橋 | 高さ1.3m、幅6.5m。入口と出口の6mでなだらかにつなぐ。わざと狭くして、混雑の見せ場にしている |
| S字 | 向きの変化 `= 0.7 × (2π/24) × cos(2πi/24)` |

- 区間の種類が見て分かるように、入口にゲート（ミニゲーム）と看板（地形）を立て、縁石の色も変える（S字は青白、坂は橙白、つり橋は木の色）

## 3. ステータスと物理

ステータスは体力・パワー・技術の3つ（[`level.md`](./level.md)）。試作では合計15のプリセットから選ぶ。相手のステータスは `[8,4,3] [9,3,3] [5,5,5] [7,7,1] [6,6,3] [7,5,3] [6,5,4]` のどれかを並べ替えたもの。

### 3.1 ステータス → 物理

| 式 | 内容 |
| --- | --- |
| `topSta = 12 + 0.8 × 体力` | 直線とハードルでの最高速（m/s） |
| `topPow = 12 + 0.8 × パワー` | ダッシュでの最高速 |
| 上記以外の最高速 | 15 |
| `accel = 4.5 + 0.7 × パワー` | 加速（m/s²）。減速は 9 m/s² で固定 |
| `uphill = clamp(1 − 勾配 × (1.6 − 0.13 × パワー), 0.35, 1)` | 上りで出せる速さの割合 |
| `grip = 10 + 1.15 × 技術` | カーブで出せる速さ `= √(grip / 曲率)` |
| `turn = 2.3 + 0.06 × 技術` | 向きを変える速さ（rad/s） |
| `slide = 4.2 + 0.2 × 技術` | 横滑りが収まる速さ。ぶつかった後の立て直し |
| `mass = 1 + 0.12 × パワー` | 衝突のときの重さ |

**どのステータスも2か所ずつ効く**ように配分している。

| ステータス | 効く場所 |
| --- | --- |
| 体力 | 見るだけの直線、ハードル |
| パワー | 上り坂、ダッシュ（＋衝突の重さ） |
| 技術 | 見るだけのS字、S字（スワイプ） |

ここは調整で2回崩れた。

- 最初は、曲がる速さと横滑りの立て直しにも技術を強く効かせていた。すると技術が低い子は、どの区間でもふらついて壁に当たってしまい、技術1の子は平均7.7着になった。今は `turn` と `slide` の係数をわざと小さくしてある
- 次に体力がダッシュにも効くようにしたら、体力だけが強くなった

配分を変えるときは、8章の手順でタイプ別の着順を測り直すこと。

### 3.2 目標速度の組み立て（この順で掛ける）

1. 基本の速さ：地形・区間ごとの最高速（3.1）
2. カーブ：この先14mの曲率の最大値 κ が 0.02 を超えたら、`√(grip / κ)` で頭打ちにする
3. 勾配：前後2mの高さの差から勾配を出す。上りは `uphill` を掛け、下りは `1 − 勾配 × 0.4` を掛ける（少し速くなる）
4. ミニゲーム区間では `0.78 + 0.44 × perf` を掛ける（perf 0.5 で等倍、1 で 1.22倍）。それ以外の区間では、調子の波 `1 + 0.03 × sin(0.35t + 走者ごとの位相)` を掛ける
5. スリップストリーム：`× (1 + 0.09 × draft)`（4章）
6. 転倒（0.7秒）なら ×0.45、加速の演出（0.4〜0.6秒）なら ×1.2
7. ゴールした後は 4 m/s

### 3.3 操舵

- 中心線を `5 + 速さ × 0.35`（5〜14）m先まで見て、そこに自分のレーン（横位置）を足した点を狙う。向きは `turn` で頭打ちにする
- 横滑りの速度成分には、毎ステップ `exp(−slide × dt)` を掛けて減らす
- 8体のレーンは `±4.2, ±3.0, ±1.8, ±0.6` に割り振る。道幅が狭い場所では、幅に比例して縮める

## 4. ぶつかり合いと追い抜き

| 項目 | 内容 |
| --- | --- |
| 当たり判定 | 半径0.75の円。めり込みは重さの比で押し戻す |
| 反発 | 反発係数0.55。ぶつかったら、軽いほうが向きを崩す |
| 追突 | 接触の向きと、後ろ側の子の進行方向の内積が 0.75 を超えたら追突として扱う。反発係数は0.05にして、後ろの子を横へ 1.5 m/s いなし、そのまま追い抜きのラインへ出す |
| ジャンプ中 | 当たり判定なし |
| 壁 | 押し戻して、壁方向の速度を ×1.45 で反転し、さらに ×0.96 |
| 演出 | 衝撃が 2.2 を超えたら火花と「ゴツン」 |

**追突を柔らかくするのは必須。** 普通に跳ね返すと、追いついた速い側だけが減速して、一度下がったら二度と上がれなくなる。

この問題を測ってみたところ、主な原因は追い上げる手段がないことだった（ぶつかりをオフにしても、順位を上げられる割合は 25% → 28% とほとんど変わらなかった）。そこで、追突を柔らかくするのに加えて、次の2つを入れた。その結果、「コースに向いている子が序盤に後ろにいたとき、最後までに抜けた割合」は 50% → 70% になった。

- **スリップストリーム**：前の子の 0.8〜7m 後ろで、横のずれが1.3以内なら効く。近いほど強く、1から0へ直線的に弱まる
- **追い抜きのAI**：6m以内の前方で横のずれが1.5以内の子がいて、自分のほうが速ければ（相手の速さ −0.5 以上）、相手の左右 1.8 の位置を候補にする。空いている側を点数で選んで、抜き切る（自分が1.5m前に出る）か、9m以上離されるまでそのラインを守る

## 5. ミニゲーム

### 5.1 共通

- どのミニゲームも出来を perf（0〜1）で持つ。区間に入った時点では0.5（ダッシュだけ0.3）
- 区間の16m手前で、実況が「次は○○！」と予告する。区間に入ると操作パネルが出て、区間を抜けたら評価を出す
- 評価は区間全体の平均で決める（ダッシュとつり橋は時間の平均、ハードルとS字は結果の平均）。S（0.88以上）、A（0.68以上）、B（0.45以上）、C。Sならカットインと、自分のアップのカメラが入る
- 操作パネルはレース画面の下側に重ねる。入力はレース画面全体で受ける（パネルにはタッチを通さない）

### 5.2 各ミニゲーム

| 区間 | 操作 | 出来の決まり方 | 手応え |
| --- | --- | --- | --- |
| ダッシュ | 連打 | 直近0.8秒の連打の速さ r から `clamp((r − 2) / 7, 0, 1)`。毎秒9回で満タン。毎秒8の速さで目標値へ寄せる | 「＋」が散る。画角が最大10度広がる。0.92を超えると「全開！」 |
| ハードル | タップ | ハードルまでの距離 d でタップを判定する。1.3〜2.2m：パーフェクト（1.0、加速0.6秒）。0.6〜3.4m：グッド（0.65）。それより手前（8mより遠いタップは無視）：早すぎ（0.1、ハードルの位置で転ぶ）。跳ばずに通過：ミス（0.1、転ぶ） | ハードルの7m手前から、時間を ×0.4 のスローにする。ジャンプは0.5秒で高さ1.3m |
| つり橋 | 画面の左右を長押し | 針の位置 x（−1〜1）が中央±0.25 にあれば1、そこから端に向かって直線的に0まで下がる | 自分の横位置が `x × (道幅/2 − 0.4)` になって、体も傾く |
| S字 | スワイプ（28px以上） | 矢印4つ。それぞれ制限0.8秒。0.45秒以内に正解なら1.0、それより遅い正解は0.7、外すか時間切れは0.1 | 正解は「キュッ！」と加速0.4秒、外すと減速0.3秒 |

つり橋の針の動き（ゆれ `drift` は時間とともに大きくなる）：

```text
drift = (sin(1.7t + φ1) × 0.9 + sin(3.3t + φ2) × 0.6) × (1.3 + 0.5t)
v'    = drift + 長押しの向き(−1/0/1) × 4.2 − 1.6v
x'    = v      （x は ±1 で止める）
```

### 5.3 相手

- 相手のミニゲームの出来は、区間ごとに `clamp(0.72 + (一様乱数3つの和 − 1.5) × 0.3, 0.25, 0.97)` で決める
- ハードルは2m手前で自動で跳ぶ。82%で成功して、失敗すると転ぶ
- 平均の0.72は、「そこそこ上手い人」が8体中3着前後になるように合わせた値（8章）。今の相手の出来はステータスとは無関係

## 6. 演出

### 6.1 カメラ

カメラは毎フレーム、次の優先順位で選ぶ。

1. スタート前：グリッドの周りを回る
2. ゴール前：先頭がゴールの16m手前に来てから、自分のゴール後2.5秒まで。ゴールラインの横に固定したカメラ
3. ハードルの直前（スロー中）：自分の横、低めの位置
4. 出来事による強制切り替え（1.3〜1.6秒）：抜いた → 自分のアップ。ぶつかった → 自分の横。Sランク・カットイン → 自分のアップ
5. ミニゲーム中と、区間の8m手前：後ろ追い。下が操作パネルで隠れるので、少し高めの位置から前を見下ろす
6. 先頭がゴールの40m手前より先：自分を正面から撮る
7. それ以外：下の割合で抽選して切り替える

見るだけの区間では、**全体：プレイヤー：ライバル ＝ 2：7：1** の割合で抽選する。8体だと群れが前後に長く伸びるので、群れの中心を撮ると誰も大きく映らない。それで以前は見にくくなっていた。

| 種類 | カメラ | 内容 |
| --- | --- | --- |
| 全体 | 後ろ上方、前方上空 | 群れの前後の長さ L に合わせて引く（後ろ：`7 + 0.35L` 後方、`6 + 0.4L` 上） |
| プレイヤー | 後ろ追い → 横 → 正面 → 肩越しの高い位置 → 低いアップ | 順番に回す |
| ライバル | 道の外側から | 自分のすぐ前（25m以内にいなければすぐ後ろ）の子。画面に「ライバル ○○」と出す |

- 抽選の重みは 2.6 / 5.8 / 1.6。強制切り替えでプレイヤーのカメラが増える分を見込んでいて、実際に映る時間の割合は 17% / 74% / 9% になる
- 1カットは2.4〜3.4秒。全体とライバルは2回連続では出さない
- **カメラの切り替えはカットにする（補間しない）**。中継のスイッチングの感じを出すため。同じカメラが続いている間だけ、追いかけを補間する
- **縦長の画面の画角**：各カメラの画角は、横長（4:3.4）の画面で決めてある。縦長だと横が見切れるので、横に見える範囲が同じになるように縦の画角を計算し直す。広げすぎると歪むので、上限は80度にしている（`fitFov`）

### 6.2 実況と画面の表示

- 実況は1秒間ロックして、優先度の高い発言だけが割り込める。主な発言：区間の予告、評価、抜いた・抜かれた、トップの交代、ぶつかった（自分以外の衝突は2秒に1回まで）、スリップストリーム（3秒に1回まで）、ラストスパート、ゴール
- 画面中央に大きな文字（「2位に浮上！」「ゴツン！」「パーフェクト！」など）を出す。自分の順位が変わったとき、文字を出すのは0.9秒に1回まで
- 集中線：ミニゲームの出来が0.85以上、アップ、ゴール前、カットインのとき。シネスコの黒帯：先頭がゴールの40m手前より先にいるとき
- 写真判定：ゴールの10m手前で、自分と誰かが2.5m以内にいたら、時間を ×0.45 のスローにする。ゴールタイムの差が0.1秒未満なら「写真判定…」を出す
- 順位は、相手と0.6m以上離れたときだけ入れ替える。そうしないと、並走中に「抜いた」「抜かれた」が連発する

## 7. 移植で気をつけること

1. **ロジックと描画を分ける。** 試作のHTMLでは、物理のステップの中から実況やエフェクトの関数を直接呼んでいる。Native では、シミュレーションを純粋なTSにして「状態と出来事の列」を返すようにし、R3F と RN のオーバーレイは結果を再生するだけにする（[`battle.md`](./battle.md) と同じ方針）
2. **固定タイムステップで回す。** 物理は 1/120 秒刻みで、スローモーションは時間に倍率を掛けて溜めていく。`useFrame` の delta で直接積分すると、端末のフレームレートで結果が変わってしまう
3. **乱数はシード付きにする。** 試作は `Math.random` を使っている。テストやリプレイ、将来の対戦で再現できるように、シードで決まる乱数に置き換える
4. **時間の基準が2つある。** 連打の速さだけは実時間（`performance.now`）で測り、それ以外はシミュレーション時間で動いている。スロー中でも連打の判定が変わらないようにするためなので、移植でも分けたままにする
5. **入力は1つのジェスチャーで判定する。** 指を置いたらタップ（連打・ジャンプ）と長押し（つり橋の左右）の両方が始まり、28px以上動かして離したらスワイプになる。gesture-handler では、タップと長押しとパンを別々に組むと競合しやすい。誤タップ防止の条件（ハードルが8mより遠いタップは無視）も残すこと
6. **3D空間の文字は作り直す。** 試作は、看板・ゲート・名札・ゴールの文字を、ブラウザの canvas 2D でテクスチャにしている。RN には DOM の canvas がないので、画像アセットにするか、名札などは画面座標に投影して RN のオーバーレイで出す
7. **CSSで作った演出は作り直す。** 集中線（`repeating-conic-gradient`）、シネスコの黒帯、カットイン、大きな文字、連打の「＋」は、Reanimated か Skia で作り直す
8. **ミニゲームのパネルを毎フレーム再描画しない。** 試作は、パネルの HTML を毎フレーム作り直している。RN で同じことをすると重いので、ゲージや針は shared value で動かす
9. **見た目のモデルを差し替える。** 試作のうんちくんは、球3つに背面の輪郭線をつけただけ。Native では既存の `poopm-3d` のモデルに差し替える。当たり判定は半径0.75の円のままにする
10. **描画の負荷を下げる。** 8体分のモデルと名札、観客のトイレットペーパー（円柱）がたくさんある。観客はインスタンス描画にまとめて、道の帯はレース開始時に1回だけ作る
11. **触覚フィードバックを足す**（試作にはない）。ゴツン、パーフェクト、ドテッ、Sランクに合わせて鳴らす。連打は1回ごとに鳴らすと重くなるので、間引く
12. **試作のまま残っている部分**：相手のミニゲームの出来はステータスと無関係。パーツとレベル（[`parts.md`](./parts.md)、[`level.md`](./level.md)）とはつながっていない。結果は表示するだけで、報酬もない

## 8. 検証のしかた

試作では、ブラウザを使わずにゲームのロジックだけを node で回した。プレイヤーの操作は機械で再現して、平均着順を測っている。

| プレイヤー | 再現した操作 | 平均着順 |
| --- | --- | --- |
| 全部完璧 | 連打は毎秒9回、ハードルは1.8m手前、つり橋は±0.08で修正、スワイプは0.3秒 | 1.6着 |
| そこそこ上手い | 連打は毎秒6回、ハードルは2.9m手前、つり橋は±0.35で修正、スワイプは0.55秒 | 3.1着 |
| 何もしない | なし | 7.7着 |

| タイプ（そこそこの腕前） | 平均着順 |
| --- | --- |
| バランス | 3.1 |
| パワー型 | 4.1 |
| 技術型 | 4.5 |
| 体力型 | 4.8 |
| 二刀流（技術1） | 6.0 |

Native でも、同じように機械に対戦させる仕組みを vitest で組む（乱数のシードを固定する）。そのうえで「上の腕前ごとの平均着順が、決めた範囲に収まる」ことをテストにしておくと、数値をいじったときにバランスが崩れたことに気づける。

## 9. 未決

- **トイレで遊ぶ負荷。** 約1分で必ず終わるので [`game-design.md`](./game-design.md) 1章の条件には収まる。ただ、連打（ダッシュ）がいきみを連想させないか、お腹が痛いときでも遊べる強度かは確かめる
