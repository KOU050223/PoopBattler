## 変更の概要

図鑑（`/collection`）の先発3枠と所持リストのキャラ表示を、2D `PoopmFigure`
から3D GLBモデルへ置き換える。表示には #169 の `PoopmFigure3D`（1体=1個別
Canvas）を使い、多数並ぶ画面向けに `useInView`（viewport ±500px）で
Canvas を出し入れする仮想化を追加した。

初版では1枚の共有全画面Canvas + drei `View` の scissor 描画を採用したが、
実機で「スクロール時にフィギュアが1フレーム以上遅れて追従する」問題を
確認。fixed Canvas はコンポジタで即スクロールするDOMと同期できず、
`getBoundingClientRect` 追従の構造的限界のため個別Canvas方式に切り替えた。
個別Canvas化で生じるコンテキスト上限（〜16個）は仮想化で回避する。

## 詳細レビュー

### poopm-figure-3d.tsx

- `useInView(hostRef, { margin: "500px" })` で内部の `Poopm3DSolo`（Canvas）
  のマウントを制御。外側の `div[role=img]` + `aria-label` は常時描画なので
  SSRマークアップ・アクセシビリティ・レイアウトは従来どおり
- 画面外に出るとアンマウントする（`once` 指定なし）ため、多数並ぶ画面でも
  ライブなコンテキスト数は可視域+マージン分に収まる。実機で 6〜9 枚の
  増減を確認（先発3+リスト可視分）
- アンマウント時に R3F が `forceContextLoss` を呼びコンテキストを即解放
  する（コンソールに `Context Lost` のログが出るがこれは解放の記録で
  エラーではない）
- 結果カード（`battle-completion-result`）も同コンポーネントを使うが、
  表示時に可視域内なので挙動は不変

### collection-list.tsx / inventory-screen.tsx

- `PoopmFigure` → `PoopmFigure3D` の素直な置き換え。`facing` prop は
  3D版が正面固定のため除去（元々 `front` 指定のみ）
- `PoopmFigure` の残使用は title 演出のみ（`title-shake-surprise`）。
  今回のissue範囲外なので据え置き

## 残リスク（目視確認推奨）

- 大きくジャンプした直後（ページ末尾→先頭など）の一瞬、フィギュア枠が
  空に見えてからCanvasが再マウントされる。500pxの先読みで通常スクロール
  では見えないが、体感は実機で確認されたい
- iOS Safari 実機での描画・スクロールは未検証（検証は Chrome）
- スクロールのたびの mount/unmount でコンテキスト生成・解放が繰り返される
  ため、長大なリストを高速に往復するとわずかなコストが乗る可能性がある
