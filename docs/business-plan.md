# 事業改善案：データ活用・BtoB

収益化のうち、蓄積データの活用（BtoB）の方針。ゲームループは [`game-design.md`](./game-design.md)、無料/プレミアムの現行方針は [`IDEA.md`](./IDEA.md)。

## 1. 結論

- 「うんちデータを直接売る」は主軸にしない。法務・ストア規約・ブランド信頼のリスクが大きく、今の規模では売るものも足りない。
- BtoBは有望だが、**集計・匿名化した「インサイト提供」と「協業」**の形にする。
- データの強化は、便データ単体ではなく**便と周辺データ（食事など）を結びつけた状態**を目指す。
- ピッチでは「データ販売」と言い切らず、**規模が出たあとの将来オプション**として置く。

## 2. データとしての価値と限界

### 強み
- 食事と排便を長期でひも付けた子どもの生活データは希少。
- 小児便秘は多く、親が気づいていないという課題がスライドの数字で示されている。

### 限界
- 子どもの自己申告（タップ入力）のため、ノイズや入力精度のばらつきがある。
- ゲームを続けた子に偏り、母集団として偏る。
- 医療・製薬用途には臨床水準の検証が必要。
- 価値が出るのは継続ユーザーが一定規模（数千〜数万）に達し、縦断データが貯まってから。

## 3. 「匿名」のレベルと売り方（日本の個人情報保護法の整理）

| 状態 | 中身 | 第三者提供 |
|---|---|---|
| 仮名化（名前を消しただけ） | ID・生年月日・地域などが残る | 個人情報のまま。同意が必要 |
| 匿名加工情報 | 識別不可・復元不可に加工 | 本人同意なしで可。ただし加工基準・公表義務あり |
| 統計情報 | 「小学生の◯%が…」などの集計結果 | 個人に紐づかず、原則自由 |

売りやすい順：

1. 集計統計・インサイトレポート（最も安全・現実的）
2. 匿名加工情報としての提供（慎重に）
3. 個別レコード提供（当面は避ける）

## 4. 現実的なBtoBの形

| 相手 | 提供・協業の形 | 狙い |
|---|---|---|
| 食品・乳酸菌・食物繊維系メーカー | 集計傾向の共有、共同企画、スポンサード | 食×排便をつなげられる点が刺さりやすい |
| 大学・小児科 | 共同研究、機能の検証 | 信頼性向上、受診目安機能の裏付け |
| 自治体・学校（食育・健康教育） | 集計データ・教材としての提供 | 個人データを使わずに社会的価値を出す |
| 一般向け | 集計インサイトレポート | 個人が特定されない統計として提供 |

## 5. データ強化の方針

便と周辺データを結びつけて価値を出す。入力負担を増やさないことが前提。

優先順位：

1. **便記録の質を保つ**（親向け価値の核。ここが雑だと周辺データも無意味になる）
2. **食事ログの構造化**（写真から食物繊維・乳製品・発酵食品などをAIで自動タグ付け）
3. **軽く取れる周辺データを追加**（水分はワンタップ、登校日・休日や睡眠は入力させず推定）

注意：項目を増やすほど離脱し、法務上の負担（要配慮個人情報の範囲）も増える。

## 6. 法務・規約・ブランドの対応

- **要配慮個人情報**: 子どもの排便記録・受診目安が該当する可能性が高い。弁護士に確認する。
- **同意設計**: 15歳未満は親権者の同意が必要。規約・プライバシーポリシーに「統計化して提供する」旨を最初から明記する。後から追加すると信頼を損なう。
- **ストア規約**: Apple / Googleのヘルスデータ第三者提供ルールを最新版で確認する（法律上OKでも審査で止まる場合がある）。
- **ブランド**: 「親が安心して使える」を崩さない見せ方にする。親課金の収益モデルとの整合を保つ。
- 法令・解釈は更新されるため、実行段階で最新内容を専門家と確認する。

## 7. 進め方（ステップ）

| 時期 | やること |
|---|---|
| 今すぐ | 食品メーカーの商品開発・ヘルスケア担当、小児科医に5〜10人ヒアリング。「どんなデータが何件あれば価値を感じるか」を聞く |
| 今すぐ | ピッチの表現を「将来、集計インサイトを提供する選択肢」に調整 |
| 開発と並行 | 同意・規約の設計方針を決め、弁護士に相談 |
| 開発と並行 | 食事ログの自動タグ付け、軽量な周辺データ取得の設計 |
| ユーザー増加後 | 集計レポート、協業、共同研究を具体化 |
