# 合成

重複したパーツやうんちくんを素材にして、パーツを強化する仕様。パーツそのものは [`parts.md`](./parts.md)。

同じ種族のうんちくんを重ねる凸（★・進化）は廃止した。うんちくんの強さはレベル（[`level.md`](./level.md)）で伸ばし、
合成で強くなるのはパーツだけにする。

## ルール

- ベースにするパーツを1つ選び、素材を**複数まとめて**消費する
- 素材にできるもの：パーツ（重複していなくてもよい）、重複したうんちくん
- 素材は消える。素材のうんちくんに付けていたパーツは外れて手持ちに戻る
- 合成でパーツの強化段階が上がる（+0〜+5）。段階ごとに効果がパーツの基本値の 20% ずつ伸び、+5 で 2倍
  （例：パワー +3% の手 → +5 で +6%）。ゲームごとの効果がすべて同じ割合で伸びる
- 強化段階の上限を超える素材の組み合わせは確定させない。溢れた分を黙って捨てない
- 進行中の取組に出ているうんちくんは素材にできない

### 素材の量（案）

| 素材 | 経験値 |
| --- | --- |
| ベースと同じパーツ | 大 |
| 同じ部位の別パーツ | 中 |
| 別の部位のパーツ | 小 |
| 重複したうんちくん | 中 |

重複を一番有利にするのは、同じパーツが出たときに「ハズレ」と感じさせないため。

### 警告

| 条件 | 強さ | 理由 |
| --- | --- | --- |
| 素材のパーツが強化済み（+1以上） | 強（赤） | 強化した分が消える |
| 素材のパーツを誰かが装備している | 注意 | 外れて、その力士が弱くなる |
| 素材のうんちくんが先発にいる | 注意 | 先発から外れ、空いた枠は別の仲間で埋まる |
| 素材のうんちくんが、同じ種族の手持ちで個体値が一番高い | 注意 | 残す方を逆にした方が強い |
| 素材のうんちくんのレベルが2以上 | 強（赤） | 上げたレベルが消える |

強（赤）の警告は UI だけに任せず、RPC 側でも確認フラグがない限り拒否する。UI のバグで、
育てたものが黙って消費されるのを防ぐ。

## 現行実装

いまのコードにあるのは、うんちくん同士の合成（凸）と進化（★）。廃止するものと、パーツの合成へ流用する性質を分ける。

| 廃止 | 場所 |
| --- | --- |
| RPC | `evolve_character`。`merge_characters` はパーツ合成用に作り直す |
| 列 | `user_characters.tier`（★）/ `rank`（凸） |
| 定数 | マイグレーションの `private.growth_percent_per_step` / `private.merge_rank_gain`、TS の `GROWTH_PERCENT_PER_STEP` / `MERGE_RANK_GAIN`（`src/features/collection/character-growth.ts`） |
| UI | 図鑑の★バッジ、凸・進化の確認 |

流用する性質：

- **育成の列はクライアントに書かせない。** 変更は definer RPC だけ。所持品を直接削除させない
- **合成は `start_battle` と同じ advisory lock で直列化する。** 合成中に取組を始められると、消える素材が出場したまま始まりうる
- **確認フラグ（今の `p_confirm_enhanced`）で育成済みの素材を守る。** 上の「強（赤）」に当たる
- **拒否の理由は SQLSTATE で返し、UI が文言を出し分ける**（`src/features/collection/growth-error.ts`、今は `PBM01`〜`PBM04`）。
  検査は `scripts/sql/rls-verify.sql` の「合成（凸）と進化（★）」を作り替える
- **`complete_battle` は個体の行を引き直さない。** 素材にされて行が消えても、完了済みバトルへの再送が
  エラーにならないよう `enemy_character_id` を返す。うんちくんを素材にできる限り、この性質は残す
