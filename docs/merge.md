# うんちくんの合成と進化

同じ種類のうんちくんを合成して凸を重ね、4凸で進化させて★を上げる育成の仕様（Issue #196）。
バトルの数値は [`battle.md`](./battle.md)、テーブル構成は [`architecture.md`](./architecture.md) を参照。

## 2つの軸

強さは「個体値」と「育成」の掛け算で決まる。

| 軸 | 持ち方 | 変わるタイミング |
| --- | --- | --- |
| 個体値 | `user_characters.hp` / `power` / `speed` | 仲間化した瞬間に抽選。以後は書き換えない |
| 育成 | `user_characters.tier`（★）/ `rank`（凸） | 合成で凸が上がり、4凸で進化すると★が上がる |

個体値を書き換えず育成を別の列に持つのは、成長カーブの調整をデータ移行なしで行うため。
元の個体値が当たりだったかも、後から読める。

## ★と凸

- ★は ★1〜★3（`tier` 0〜2）
- 凸は各★で 0〜4（`rank`）
- 4凸の個体は進化できる。★が1上がり、凸は0に戻る。進化は自動ではなく、ユーザーが選ぶ
- ★3・4凸が最大

## 実効値

★と凸を進行度 `p = tier × 4 + rank`（0〜12）にまとめ、個体値に掛ける。

```text
実効値 = round(個体値 × (100 + 伸び率 × p) / 100)
```

★1・4凸 と ★2・0凸 は同じ進行度になるので、進化直後に弱くならない。

| レアリティ | 伸び率/段 | 最大倍率 | 合成1回の凸 | ★3・4凸までの必要数 | Power 基準の素 → 最大 |
| --- | --- | --- | --- | --- | --- |
| common | 5% | ×1.60 | +1 | 13体 | 20 → 32 |
| rare | 7% | ×1.84 | +1 | 13体 | 26 → 48 |
| epic | 8% | ×1.96 | +2 | 7体 | 32 → 63 |
| legendary | 10% | ×2.20 | +4 | 4体 | 38 → 84 |

- 最大まで育てた common（32）は、素の legendary（38）に届かない。レジェンドはレジェンドのまま
- legendary は重複を引きにくいので、1回の合成で4凸上がる。重複1体で即進化できる
- 育てた rare は素の legendary を上回るが、育てた legendary には届かない

実効値はバトル開始時に `start_battle` がスナップショットへ載せる。図鑑の表示は
`src/features/collection/character-growth.ts` が同じ式で計算する。定数は
マイグレーションの `private.growth_percent_per_step` / `private.merge_rank_gain` と
TS の `GROWTH_PERCENT_PER_STEP` / `MERGE_RANK_GAIN` の2か所にあり、必ず一緒に変える。
丸めは両方とも整数演算（`(base × percent + 50) / 100`）で、浮動小数の誤差で1ずれないようにしている。

## 合成のルール

ユーザーがベースを選び、同じ種類の素材を1体消費する。

- 合成できるのは同じ `character_id`（種族）同士だけ
- 素材の★・凸・個体値は引き継がない。素材の行は削除する
- 合成で上がる凸はレアリティごとに固定（上の表）
- 現在の★の上限（4凸）を超える合成は拒否する。溢れた凸を黙って捨てない。進化してから合成し直す
- 進行中バトルのパーティにいる個体は、ベースにも素材にもできない

### 警告

合成前の確認で、次の場合に警告を出す。

| 条件 | 強さ | 理由 |
| --- | --- | --- |
| 素材が育成済み（★2以上 or 1凸以上） | 強（赤） | 育てた分が引き継がれずに消える |
| 素材の個体値がベースより高い | 注意 | 逆をベースにした方が強く育つ |
| 素材が先発にいる | 注意 | 先発から外れ、空いた枠は別の仲間で埋まる |

個体値の比較は `HP / 12 + Power + Speed` の総合点で行う（HP は他の2値の12倍の桁で振られるため）。
3値のどれか1つでも上なら警告、にすると、独立に振られた個体同士ではほぼ毎回出てしまう。

育成済み素材の警告は UI だけに任せない。`merge_characters` は確認フラグ
（`p_confirm_enhanced`）が true でない限り育成済みの素材を拒否する。UI のバグで警告が
出なかったときに、育てた個体が黙って消費されるのを防ぐ。

## サーバー側（RPC）

クライアントは `tier` / `rank` を直接書けず、所持個体を直接削除することもできない
（UPDATE / DELETE の権限もポリシーも無い）。変更は definer RPC だけが行う。

| RPC | 内容 |
| --- | --- |
| `merge_characters(p_base_id, p_material_id, p_confirm_enhanced)` | 素材を削除し、ベースの凸を上げる |
| `evolve_character(p_user_character_id)` | 4凸の個体を次の★・0凸にする |

`merge_characters` は `start_battle` と同じ advisory lock で直列化する。合成中にバトルを
開始されると、消える素材がパーティに入ったまま始まりうるため。

拒否の理由は SQLSTATE で返し、UI が文言を出し分ける（`src/features/collection/growth-error.ts`）。

| SQLSTATE | 意味 |
| --- | --- |
| `PBM01` | 素材が育成済みで、確認フラグが無い |
| `PBM02` | 合成すると4凸を超える |
| `PBM03` | どちらかが進行中バトルのパーティにいる |
| `PBM04` | 進化できない（4凸未満、または★3） |
| `22023` | 同じ個体同士・別の種族同士 |
| `42501` | 本人の個体ではない（存在の有無は区別しない） |

検査は `scripts/sql/rls-verify.sql` の「合成（凸）と進化（★）」にある。

### complete_battle との関係

合成で `user_characters` の行が消えるようになったため、`complete_battle` の冪等な再呼び出し
（完了済みバトルへの再送）は、仲間化した個体の行を引き直さず `enemy_character_id` を返す。
行を引き直す実装のままだと、仲間化した個体を素材にしてからリトライしたときに `character_id`
が null になり、クライアントが「仲間化したのに個体が無い」を契約違反として扱って、
完了済みのバトルがエラーのまま抜け出せなくなる。

## 既知の制約

- 凸の上がり幅は「0凸から始まり、上がり幅の倍数ずつ増える」前提で、epic（+2）が3凸のような
  「4凸未満なのに合成も進化もできない」状態には通常の操作ではならない。上がり幅を変えるときは、
  既存個体がこの状態に入らないかを確認する
- 見た目は図鑑の★バッジだけ。3Dの演出は別 Issue で扱う
- 交換（#197）で育成済みの個体を出せるかは #197 側で決める
