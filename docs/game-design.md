# ゲーム設計：記録 → 10秒レース → 継続で育つ

ゲームループの正本。企画の全体像は [`IDEA.md`](./IDEA.md)。**実装はまだ旧ループ（トイレでHP制オートバトル）のまま**。
前の案（トイレで記録、寝る前にガチャ・育成・相撲）は [`game-design-bedtime.md`](../docsArchive/game-design-bedtime.md)。相撲はサブモードとして残す（[`battle.md`](./battle.md)）。

社内の呼び名は「うマ娘」。製品名には使わない（「ウマ娘」の商標に触れるため）。キャラは今のうんちくんのまま。

## 1. 方針

- トイレでは記録し、その直後に**10秒の自動レース**を見る。操作はない。
- 育成は**記録を続けた日数**で進む。レースの着順は育成に関係しない。
- 記録をごまかしても得をしない仕組みにして、データの質を守る。

### 変更の理由

旧ループ（トイレで操作するバトル）には、次の問題があった。

- トイレでスマホを操作するのはマナーが悪く、長居やいきみすぎにつながる
- 1回がすぐ終わる一方で、操作する余裕がない
- お腹が痛いときに遊ぶのはつらい

レースを「見るだけ・10秒固定」にすると、これらを避けたまま「トイレで何か起きる」楽しみを残せる。寝る前のセッションを前提にしないので、スクリーンタイムの心配も小さくなる。

## 2. 基本の流れ

| タイミング | 内容 |
|---|---|
| トイレ | 便の形・色・食事などをタップで記録 → 10秒レースを観戦 |
| 次にアプリを開いたとき | 前日までの未反映の日をまとめて反映 → ポイントを振る |

- 反映は「次にアプリを開いたとき」に行う。夜中にサーバーで一斉に計算はしない。開かなかった日も取りこぼさない。
- 日付の区切りはサーバー側で決める。端末の時計を変えて日をまたぐズルを防ぐため。
- レースは記録するたびに走るが、育成に効くのは1日分だけ。
- ポイントは体力・パワー・技術（案）に振る。どのゲームでも共通（[`level.md`](./level.md)）。
- 食事の記録は、うんちくんの育成になる（1日1回分で頭打ち、食品群で伸びる値が決まる）。
- 記録した翌日（次に開いたとき）に、ガチャを引く石がもらえる。量の決め方はポイントと同じ（3章の3）。
- パーツはガチャで出る。部位は頭・手・足。同じパーツでもゲームごとに効く値が違う（[`parts.md`](./parts.md)）。

## 3. ズルの意味をなくす仕組み

ここでの「ズル」は、出ていないのに記録して報酬を得ること、またはデータを盛ること。

1. **便の中身で何も変えない**
   - レースの着順も育成も、便の形・量で変えない。「良い便ほど得」にすると、悪い便を隠す動機になり、便秘発見という本来の価値が壊れる。
   - コースや天気など、見た目だけの違いはつけてよい。
2. **「出なかった」も1日の記録として数える**
   - 嘘をつく理由がなくなり、便秘判定にも有用なデータになる。
3. **ポイントは1日分で決まる**
   - 記録がうまくいった日は通常のポイント。何回記録しても増えない。
   - 後入力の日、信頼度が低い記録の日は減らす。両方でも同じ量。
   - 「うまくいった」は記録の仕方（その場で記録した・不自然さがない）で決め、便の中身では決めない（1の原則）。
4. **強さは継続で伸びる。レースの結果は関係しない**
   - 着順を育成に効かせると、運のいい結果を引くために記録を増やす動機になるため。
   - 数えるのは連続日数ではなく、記録した日の通算。途切れてもペナルティはない。1日抜けた子がやめたり、お腹の調子が悪い日に無理をしたりしないようにする。
   - 1日1回で頭打ちなので、強さが記録日数に比例しても水増しはできない。

## 4. データ側の対策

ズルを完全に防ぐのは難しいため、**ズルをしてもデータが汚れない**設計にする。

- 記録時刻は自動で付け、後から編集できないようにする。
- 後入力は同日のみ許可し、「後入力」フラグを付けて、集計や受診用サマリーでは重みを下げるか除外する。
- 短時間の連続記録などの不自然なパターンは、裏で「信頼度低」として統計から外し、その日のポイントを減らす。判定の基準は本人に見せない（基準が分かると、すり抜け方も分かるため）。
- 親向け画面は要約中心にし、子どもが監視されていると感じないようにする（監視感は嘘を増やす）。

## 5. レースの演出

着順は報酬に関係しないので、レースは「育ったことが見える場所」として作る。

- 反映後の最初のレースで、育った分を匂わせる演出を入れる（ジャンプなど、前はしなかった動き）。
- 「前より速くなった」「ライバルに追いついた」が、数値を見なくても分かるようにする。

## 6. 未決

- 育成まわり（ポイント量、ステータスの換算、上限など）は [`level.md`](./level.md) の未決
- レースの相手と着順の決め方（ステータスと運の配分）
- 1日にもらえる石の量と、ガチャ1回の値段
- パーツのゲームごとの効果表。まわしの廃止に合わせた [`parts.md`](./parts.md) / [`merge.md`](./merge.md) の書き直し
- 相撲サブモードをいつ遊ぶか
- ポイントが減った理由を本人にどう伝えるか（後入力は理由を出せるが、信頼度低は基準を伏せたい）
- 信頼度スコアの具体的な基準
- ピッチの訴求（「トイレの時間がレースになる」「続けるほど育つ」）
