# ゲーム設計：記録 → 寝る前に遊ぶ

ゲームループの正本。企画の全体像は [`IDEA.md`](./IDEA.md)。**実装はまだ旧ループ（トイレでバトル）のまま**で、現行の挙動は [`web-spec.md`](../docsArchive/web/web-spec.md) と旧バトル仕様 [`web/battle.md`](../docsArchive/web/battle.md)。バトルは相撲に決定済みで、仕様は [`battle.md`](./battle.md)。検討経緯は [`battle-brainstorm.md`](../docsArchive/battle-brainstorm.md)。

## 1. 方針

- トイレでは**短い記録だけ**を行い、ゲーム本編は**寝る前**に遊ぶ。
- 記録すると、ゲームに使える素材（パーツ・対戦相手など）が手に入る。
- 記録をごまかしても得をしない仕組みにして、データの質を守る。

### 変更の理由
- トイレでの長時間のスマホ利用は、長居やいきみすぎにつながりうる。「トイレでは5〜10秒で記録」にすると、親にも説明しやすい。
- 記録とゲームを分けることで、「毎晩の習慣」として定着させやすい。

## 2. 基本の流れ

| タイミング | 内容 |
|---|---|
| トイレ | 便の形・色・食事などをタップで記録 → 「ドロップ」（ガチャ3回分）を獲得（短い演出のみ） |
| 寝る前 | たまったドロップで、孵化・育成・バトルを遊ぶ（1回数分で終わる設計） |

- ドロップ例：うんちくんのたまご、パーツ、対戦相手の種。
- トイレ側にも小さな「入手の快感」を残し、記録の動機を維持する。

## 3. ズルの意味をなくす仕組み

ここでの「ズル」は、出ていないのに記録して報酬を得ること、またはデータを盛ること。

1. **報酬を便の中身に連動させない**
   - 「良い便ほど得」にすると、悪い便を隠す動機になり、便秘発見という本来の価値が壊れる。
   - どんな便でも報酬は同じにする。
2. **「出なかった」も同じ報酬にする**
   - 出ていない日も記録でき、同じ報酬をもらえる。嘘をつく理由がなくなり、便秘判定にも有用なデータになる。
3. **報酬は1日分で決まり、毎日安定して出す**
   - 記録がうまくいった日はガチャ3回。何回記録しても増えない。
   - 後入力の日、信頼度が低い記録の日は1回。両方でも1回。
   - 「うまくいった」は記録の仕方（その場で記録した・不自然さがない）で決め、便の中身では決めない（1の原則）。
   - 続けていれば毎日同じだけ引けるので、ごまかすより正直に続けるほうが得になる。
4. **強さはストーリーで伸ばす。記録日数には比例させない**
   - 主軸はレベルで、ストーリーの取組に初めて勝つと上がり、伸ばす値を選べる。上限は章で開く（[`level.md`](./level.md)）。
   - ガチャで手に入るパーツも強さに効く。重複は合成でパーツの強化に使う（[`parts.md`](./parts.md)、[`merge.md`](./merge.md)）。
   - 未クリアの取組に挑めるのは記録した日だけ。記録は「進める権利」で、強くなるには勝つ必要がある。
   - 強さの幅は約1.3倍までで、腕（読み・パリィ）の差を超えない。
5. **食事写真と結びつける**
   - ドロップの属性を直近の食事から決める（現状の「肉」「乳」などの属性に合う）。
   - 「いろいろ食べると面白い」動機になり、便の回数を増やす動機にはならない。

## 4. データ側の対策

ズルを完全に防ぐのは難しいため、**ズルをしてもデータが汚れない**設計にする。

- 記録時刻は自動付与し、後から編集不可にする。
- 後入力は同日のみ許可し、「後入力」フラグを付けて、集計や受診用サマリーでは重みを下げるか除外する。
- 短時間の連続記録などの不自然なパターンは、裏で「信頼度低」として統計から外し、その日のガチャを1回にする。判定の基準は本人に見せない（基準が分かると、すり抜け方も分かるため）。
- 親向け画面は要約中心にし、子どもが監視されていると感じないようにする（監視感は嘘を増やす）。

## 5. 注意点・課題

- **ピッチの訴求変更**: 「トイレの時間がバトルになる」が現在の核。「記録がゲームの素材になる」「毎晩の習慣になる」に言い換える必要がある。
- **スクリーンタイム**: 寝る前のプレイは親が気にする点。1日のプレイ時間上限や、就寝前の終了を促す演出を入れる。
- **継続報酬の設計**: 連続ログイン等の報酬は、便の回数ではなく**記録を続けた日数**に連動させる。
- **記録とゲームの時間差**: 次の日も記録したくなる仕掛け（翌日のイベント、ドロップの孵化待ちなど）を検討する。

## 6. 今後の検討事項

- ドロップの種類と、食事属性とのひも付けルール
- 寝る前プレイの1セッションの長さ・内容
- 記録なしの日（「出なかった」）の演出
- ガチャが1回に減ったことを本人にどう伝えるか（後入力は理由を出せるが、信頼度低は基準を伏せたい）
- 連続日数の節目のボーナスの量
- 信頼度スコアの具体的な基準
