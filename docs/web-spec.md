# Webアプリ現行仕様

現行のWeb版（`apps/web`、Next.js PWA）がユーザーに見せている振る舞い・ルールの仕様書。
Native移行の写し元として「何が正解か」をここに固定する。バトル内部ルールの詳細は [battle.md](./battle.md)、構成は [current-architecture.md](./current-architecture.md) を参照。

## 概要

- 排便の状況でキャラクター「プーモン」を育てて戦うバトルゲーム。記録 → バトル → 仲間化ガチャ → コレクションがコアループ
- タイトル: **踏ん張れ！ブリュレイド！！** / 開発名: PoopBattler / 対象: iPhone PWA 先行
- 匿名サインインで即プレイ開始。Google連携は任意。課金はStripeサブスクリプションでレポート機能のみ解放

## 画面構成

| パス | 画面 | 内容 |
|---|---|---|
| `/` | タイトル | ロゴ + 「はじめる」。画面シェイクでプーモン出現ギミック（認可不要な端末のみ権限要求ボタン） |
| `/battle` | バトル | 3Dステージのターン制バトル。スピード切替（1x/2x、localStorage保存）、常時画面点灯（Wake Lock）、モーション権限はバトル開始時に要求 |
| `/collection` | コレクション | 仲間一覧（2Dフィギュア・HP/攻/速）＋パーティ編成（3枠、入替） |
| `/logs` | 記録・履歴 | 食事ログの記録/一覧、バトル履歴（排便ログ・仲間化結果・食事記録の有無） |
| `/report` | レポート | 週次レポート。未課金はティーザー |
| `/account` | アカウント | サインイン状態、Google連携、サブスク状況、退会 |

バトル完了後は `/battle` 内でモーダル遷移：排便ログ → 食事記録セッション → 仲間化AR（成功時）→ 結果表示。

## 認証・アカウント

- 初回アクセスで匿名ユーザーとして自動サインイン（cookieベースのセッション）
- Google連携は任意。`/account` からリンク開始、コールバックは `/` に戻る（linked / error をクエリで表示）
- サインアウトすると次回アクセス時に新しい匿名ユーザーになる
- 退会はアカウント画面から。課金済みの場合の導線はStripe Customer Portal経由
- タブレットもスマートフォンと同じ縦持ちUI

## バトル

詳細ルール（属性相性、速度順、勝敗、スタッツ計算）は [battle.md](./battle.md)。ここではUX面の仕様のみ。

- `start_battle` は**進行中バトルがあればパーティ指定を無視して既存バトルを再開**する。未完了バトルを捨ててやり直す導線はない
- **敗北してもサーバーのバトル行は `active` のまま残る**。次に開始を押すと同じ敵・同じ `party_snapshot` で再開される（実質リマッチ）。排便ログ・仲間化は勝利時のみ
- 敵はサーバー側で選定：7属性からランダムに属性を1つ選び、その属性のキャラをランダムに1体。該当なしなら `normal` 属性から選ぶ。クライアントは敵を指定できない
- バトル中のUI：3Dステージ、被弾演出、HP表示、速度切替（1x/2x）、Wake Lock による画面点灯維持、モーション権限の要求
- 勝利後の完了フロー（`complete_battle_with_symptoms` RPCで一括確定）:
  1. **排便ログ入力**（必須・このタイミングでしか記録できない）
  2. **食事記録セッション**（任意・その場で何件でも追加できる）。セッション内で最後に記録した食事が `meal_log_id` としてバトルに紐づき、ガチャの投げ入れ演出に使われる
  3. 結果確定 → 仲間化判定
- 完了はクライアントに確定結果を返すため、リロードしても二重計上されない

### パーティ編成

- コレクション画面で3枠を編成。枠の指定・入替は `swapLineupSlot` セマンティクス（空→配置、同士→入替、選択解除）
- 編成は **localStorage（端末ローカル）**。サーバーにはバトル開始時の `party_snapshot` としてのみ残る
- 開始時にクライアントは編成の `user_characters.id` だけを送る。**HP/攻/速はサーバーがDBから確定**し、クライアントの値は信用しない。未編成なら所持個体の新しい順に最大3体を自動選択
- 所持個体が3体に満たない場合、**不足分はレンタル個体で埋める**（`normal` 属性のキャラ優先、最終フォールバックは敵と同じキャラ）。手持ち0体でもバトルは開始できる

## 仲間化（ガチャ）

バトル勝利時、`companionship_result = random() < chance(食事ログ件数)` をサーバー側で決める。

| 食事ログ件数（その時点の累計） | 仲間化確率 |
|---|---|
| 0件 | 0%（抽選自体なし） |
| 1件 | 50% |
| 2件 | 75% |
| 3件 | 85% |
| 4件以上 | 90% |

- 確率の分母はそのユーザーの**食事ログ総件数**（バトルとの紐づけ `meal_log_id` は確率に影響しない）
- 仲間になるキャラクターは敵キャラクター自身（ランダム選択された敵がそのまま加入）
- 失敗した場合、結果画面で「再抽選できない」旨を明示

### 仲間化AR演出

成功時のみ、ガチャ演出としてARステージを挟む。ステージ遷移：

`staging → throw → shake → reveal → summary`

- **staging**: カメラプレビュー + 便器検出（coco-ssd）。便器が見つかるまで待機、検出できない場合はフォールバック
- **throw**: 食事写真を便器へ投げ込む演出（モーション/スワイプ）
- **shake**: 便器が揺れる演出
- **reveal**: 3Dキャラクターが這い出す（GachaStage3D）
- **summary**: 獲得結果

- カメラ非対応・権限拒否時は3D演出のみ（ARなし）にフォールバック
- `prefers-reduced-motion` では throw/shake をスキップ
- スキップボタンでいつでも結果表示へ抜けられる

## 記録

### 食事ログ

- 記録タイミング：**いつでも**（ログ画面のフォーム）＋ バトル後の食事記録セッション
- 項目: 写真（必須）、食事した日時（`datetime-local`、デフォルト現在・変更可）、食事グループ（複数選択）、メモ（任意・500字）
- **写真はIndexedDBに保存されサーバーへは送信しない**。サーバーにはメタ情報のみ
- 制約: JPEG/PNG/WebP、5MB以下
- 食事グループは件数ではなく種類の選択（`enforce_meal_food_group_integrity` で整合性を担保）

### 排便ログ

- **バトル勝利後の完了フロー内でしか記録できない**（バトル＝排便のメタファー）
- 項目: 硬さ（1-7の7段階、ブリストル尺度相当）、量、色（スウォッチ選択）、出やすさ、症状（複数選択・任意）

### 履歴

- `/logs` でバトル履歴を表示。各エントリに排便ログ内容、食事記録の有無、仲間化結果（獲得キャラ/失敗/対象外）を表示

## コレクション

- 獲得順（新しい順）でプーモンを一覧表示。各カードに2Dフィギュア、名前、属性、レアリティ、HP/攻/速、獲得日時
- 属性は7種の食べ物系（curry / vegetable / spicy / meat / sweet / dairy / normal）。レアリティは4段階（common / rare / epic / legendary）
- キャラクターはマスター `characters`（seed済み8体）+ ユーザー所持 `user_characters`。ステータスは個体別で、加入時にレアリティ基準で抽選される：Power/Speed 基準 20/26/32/38・HP はその12倍・振れ幅 ±4/6/8/10（common/rare/epic/legendary）
- 敵の基準は別系統：HP 480±60・Power 26±4・Speed 20±4
- 仲間になるのは**倒した敵キャラクター自身**（`enemy_character_id` が `user_characters` に入る）

## レポート

- 週次レポート。週は **JST月曜始まり**
- 内容: 週サマリ（排便回数・記録日数）、前週比較、硬さ/量などの内訳、食事と排便の相関分析
- 相関分析: 排便の **24〜48時間前**の食事を紐づけ、サンプル **2件未満は分析表示しない**
- **未課金はティーザー表示**: 回数などの数値だけを実データで出し、内訳・分析はプレースホルダー（ダミー描画）。スタイルを消せば読めるような隠し方はしない（テストで担保）

## 課金

- Stripe Checkoutによる**サブスクリプション**（レポート機能のみ解放。ゲーム本体は無料）
- Checkout開始には **Google連携が必須**（匿名ユーザーのままでは購入不可 — 課金の紐づけ先を失わないため）
- 有効判定: `subscriptions.status ∈ {active, trialing}` かつ `current_period_end > now()`
- 期間終了で権利失効 → ティーザーに戻る。解約は期末キャンセル（at period end）
- 管理・解約は Stripe Customer Portal から。Webhook（`checkout.session.completed` / `customer.subscription.*` / `invoice.*` 系）で `subscriptions` を更新

## PWA

- Service Worker + manifest でインストール可能
- **初回バトル完了後**にインストール促進カードを出す（localStorageで一度だけ記憶）
- 出し分け: `beforeinstallprompt` 対応ブラウザはネイティブプロンプト、iOS Safariは手動手順案内、その他Chromiumは案内表示
- タブレットでも同UI

## 3D・演出の所在

- 3D（three + R3F + drei + GLB）が使われているのは: バトルステージ、仲間化ガチャ、結果画面の獲得フィギュア、プーモンの演出
- 2D（`PoopmFigure` CSS/画像）が使われるのは: コレクション一覧、履歴、タイトル演出
- GLB: `poopm_base.glb` + 頭部バリエーション（hat-a〜f）とアクセサリ（acc hat-a〜f）

## i18n・保存データ

- ja/en対応（next-intl、cookie `locale`）。内部IDはUIに出さない

| データ | 所在 |
|---|---|
| アカウント・認証 | Supabase Auth（cookie） |
| バトル・記録・コレクション・課金 | Supabase（RLS下） |
| 食事写真 | IndexedDB（端末のみ） |
| パーティ編成 | localStorage |
| バトル進行中スナップショット | sessionStorage（タブ単位・復帰用） |
| バトル速度・PWA促進済み・ロケール | localStorage / cookie |
