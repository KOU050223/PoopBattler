# 画面シーケンス（web版実測 / native対照）

web版を実際に動かして確認した画面遷移。native移行の到達点はこのシーケンスをなぞること。
各画面の実写は `web-screenshots/` にある（390x844、匿名セッション状態）。

## web版の画面と遷移

```
/ (タイトル)
  ロゴ + タグライン「トイレの時間が、バトルになる。」
  [はじめる] → /battle
  「登場演出プレビュー」「シェイクでなかまをよぶ」(モーション権限の要求もここ)
```

共通シェル（(app)グループ内）:
- ヘッダー: 左=ロゴ(→/`)、右上=アカウント状態(未連携→ログイン導線→/account)・言語切替
- ボトムナビ: **バトル / 記録(/logs) / 図鑑(/collection)** の3項目のみ

```
/battle
  未開始: 説明 + [バトルをはじめる]
  押下 → start_battle（進行中があれば再開。敗北後も同じ敵でリマッチ）
  バトル中: 3Dステージ・HP・1x/2x・Wake Lock
  勝利 → 同一画面内モーダル遷移:
    排便ログ(必須) → 食事記録セッション(任意・何件でも)
    → complete 確定 → 仲間化成功時のみ AR(staging→throw→shake→reveal→summary)
    → 結果画面（獲得キャラの3Dフィギュア）

/logs (「記録」タブ)
  上部: 「今週のレポート(プレミアム)」カード → /report
  本体: バトル履歴一覧（排便ログ内容・食事有無・仲間化結果）
  ※食事記録はここには無い

/meals (独立ページ。ナビには出ない)
  導線: コレクション空状態の「食事を記録する」ボタン
  今日のごはんフォーム（写真必須・食品群複数選択）+ 記録一覧

/collection (「図鑑」タブ)
  先発3枠（空き=レンタル埋め表示）
  所持一覧（2Dフィギュア・HP/攻/速）
  空状態: [食事を記録する→/meals] [バトルへ行く→/battle]

/report
  未課金→ティーザー / 課金→週次レポート（JST月曜始まり）

/account (ヘッダー右上から到達)
  匿名警告カード → [Googleアカウントと連携する] [以前にGoogle連携した記録に戻る]
  課金状況・アカウント削除
```

## native版との差分（要対応）

| # | web | native現状 | 差分 |
|---|---|---|---|
| 1 | `/` タイトル画面あり | indexタブが直接バトル画面 | **タイトル画面が無い**。ロゴ・はじめるCTA・シェイク演出の移植が必要 |
| 2 | ボトムナビ3項目 | タブ5項目（+report/account） | webはレポート=logs内カード経由、アカウント=ヘッダー右上経由。並びを揃えるか要判断 |
| 3 | `/meals` 独立ページ | logsタブ内Segmented[meals/battles] | 構成は異なるが機能はある。webは「食事記録」と「バトル履歴」を別画面、nativeは1タブ内の切替 |
| 4 | `/report` は `/logs` 内カードから | 独立タブ | 導線の違い |
| 5 | `/account` はヘッダーから | 独立タブ | 同上 |

完了フロー（排便ログ→食事セッション→確定→AR→結果）の順序はnative実装と一致済み（コード確認）。

## メモ

- webの食事記録への通常導線はコレクション空状態のみ（タブにもログ画面にも無い）。specの「いつでも記録できる」の実体は /meals 直URL＋完了フロー内セッション。
- タブ構成の差（nativeが5タブ化した）は意図的な判断か未確認。揃える方向なら、report/account をタブから外して logs 内カード + ヘッダー導線に寄せる必要がある。
